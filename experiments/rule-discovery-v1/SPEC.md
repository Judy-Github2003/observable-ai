## 0. 核心指令（先读）

**保留现有“学前教育 → 小学 → 初中 → 高中”的知识课程路线，但暂停扩展小学 72 单元。优先完成一个独立的 V2 实验：使 Kotlin 学生在教师只提供样本真值、没有直接提供规则的条件下，自主生成候选规则，主动选择验证样本，淘汰错误候选，并把验证得到的新规则保存下来，在新对象上独立执行。**

这是一项**最小可验证的归纳式规则学习**实验，不是训练神经网络，不是通用 AGI，也不是“让 DeepSeek 自动写好 24 课的操作函数”。

本轮的唯一核心问题：

> **当目标规则事先不存在于学生规则库时，学生能否通过受控观察、候选枚举、主动验证与证据更新，独立确定一条可在新对象上运行的规则？**

请不要为了让报告好看而扩大功能、暗中写入答案或调整判分标准；任何失败都要保留。

## 2. 严格定义“学生学到了一条规则”

假设教师掌握一个不可直接读取的目标判定函数 `f(x)`，学生只能访问：

- 对象的显式属性（例如颜色、形状），以及已给出的标签与证据 ID；
- 一个有限、公开的候选表达式语法（即**允许学什么形式的规则**）；
- 一个查询池：可看见待询问对象的属性，但看不见它们的真值；
- 教师逐条返回的 `true / false / unknown` 观察结果；
- 内置的候选生成、证据一致性检查、查询选择、规则解释和持久化机制。

学生需要完成：

1. **列候选**：根据属性模式与语法自动枚举多个候选，不由教师直接把最终条件作为代码交付。
2. **筛候选**：利用已有正反证据排除与观察不一致的候选。
3. **认知未知**：若多个候选都可解释现有证据，返回“不足以唯一判断”，而不是随意挑一个。
4. **主动问证据**：从查询池选出能最大程度区分候选的对象，向教师请求其标签。
5. **更新与修正**：记录新证据、候选淘汰原因、查询选择依据，保留完整历史。
6. **固化规则**：只有在定义好的可辨识条件成立时，才将候选规则晋升为可执行、带来源的学生规则。
7. **离线验证**：冻结规则和学生执行程序、关闭教师，换一组从未出现过的对象/ID进行预测。

**归因用词必须精确**：

- 候选生成算法、规则表达式语法、查询策略：`designer_programmed`（由开发者预置）。
- 本次实例化的具体规则：可以标 `student_induced`（学生从证据中筛选/归纳得到），**但不能**写成“学生发明了归纳算法”。
- 教师输出：`teacher_observation`（只提供被问对象的标签）。
- 审查器输出：`external_audit`，不能记作学生自己的验证。

**通过本轮只代表：在限定假设空间内完成规则归纳与迁移；不代表开放世界、自发发明任意程序或独立理解自然语言。**

## 3. 第一个强制演示：红色圆形判定

教师在本地真值源里维护**隐藏规则**：`合格 = (颜色 == 红色) AND (形状 == 圆形)`。目标规则仅用于教师答题与独立验收，学生不得读取。

向学生提供以下世界（世界名、对象名仅用于定位，不能作为候选条件）：

| 对象 ID | 颜色 | 形状 | 初始对学生可见的标签 |
|---|---|---|---|
| A | 红色 | 圆形 | `true` |
| B | 蓝色 | 方形 | `false` |
| C | 红色 | 方形 | `unknown`（未询问） |
| D | 蓝色 | 圆形 | `unknown`（未询问） |

学生在 A、B 两个观察后，**不能**直接推出唯一规则。比如这些候选与已知样本都相容：

- `颜色 == 红色`
- `形状 == 圆形`
- `(颜色 == 红色) AND (形状 == 圆形)`

允许学生采用信息增益、版本空间划分或等效的确定性策略来挑选 `C` 或 `D`。查询真值源时：`C=false`、`D=false`。在充分区分候选后，学生才能固化 `红色 AND 圆形` 规则。**不规定必须先查询 C 还是 D，但要解释选取原因。**

完成后再创建 E、F、G 等全新对象 ID 测试。学习器只能用“颜色、形状”规则计算，不能引用 A/B/C/D 的 ID 映射表来答题。

**必须增加一条反作弊约束**：若给出的样本或查询池不足以区分所有非等价候选，最终状态必须是 `unknown/ambiguous`；不能因为预置“优先选 AND”就宣称发现了目标。对于在允许的全部属性组合上确实等价的不同语法表示，可做规范化并给出等价证明，不把它们当作歧义。

## 4. 这轮实现什么：最小学习内核

### 4.1 有界规则表达式（第一版）

采用安全、可解释的 AST / JSON DSL，先只支持：

```json
{
  "op": "and",
  "clauses": [
    { "field": "颜色", "eq": "红色" },
    { "field": "形状", "eq": "圆形" }
  ]
}
```

表达式空间限定为：

- 单条件：`field == value`；
- 双条件：`(field_1 == value_1) AND (field_2 == value_2)`，不同字段、不允许重复条件；
- 第一轮**不支持** `OR`、任意嵌套、函数调用、外部 I/O、任意 Kotlin 代码或 LLM 即兴改写。

候选来源于**公开属性 schema 与允许的值域**，不是由教师给出目标组合。候选必须去重、规范化，给出确定性排序；样本不足时应保留多个候选。

属性缺失时，单个条件为 `unknown`，整体使用适当的三值逻辑（已知有一项 `false` 可判 `false`；否则含 `unknown` 就不能硬判 `true`）。不同证据对同一对象同一标签正反冲突时输出 `conflict`，保留冲突双方，不默认取最后写入。

### 4.2 假设维护器

每条候选维护：

- 规则表达式与规范化 hash；
- 与哪些证据一致/不一致；
- 是否仍可行、若淘汰由哪条证据导致；
- 当前候选空间大小及其变化；
- 规则的获取方式及算法版本。

追加一条教师观察后，必须能从历史事件复现筛选过程。不准只保留最终胜出者而丢失淘汰记录。

### 4.3 主动查询器

只能访问查询池的**属性与公开元数据**，不能预先读取待询问标签。

建议实现：对每个待询问对象计算不同候选的 `true/false/unknown` 预测分布，优先选择最能把剩余候选分开的对象；同分使用稳定排序。若没有能区分候选的对象，返回 `need_more_discriminating_examples`，而不是重复询问同一无效对象。

将“为什么问这个样本”记录为结构化信息，例如候选数、各预测分组大小、选择分数和打破平局的方法。信息增益公式或其他策略由 DeepSeek 自选，但必须是**在查询前**计算，不能看答案后补理由。

### 4.4 晋升与执行

只有满足以下全部条件才能固化为可执行学生规则：

- 历史标签不存在未解决冲突；
- 至少有真实的正、负观察；
- 当前证据与候选结果一致；
- 在本次声明的**完整、有限属性取值空间**内，剩余候选唯一，或已证明语义等价；
- 记录用于晋升的证据 ID、候选淘汰证明、限制条件和规则版本。

不满足时规则状态为 `provisional / ambiguous / conflict`，不可伪装为已掌握。

已晋升的规则由 Kotlin 解释器直接运行；当输入缺少必需属性时返回 `unknown`。教师关闭后依旧能够按规则计算新对象。

### 4.5 持久化与审计

最低要求：

- 训练前后重启仍能读取观察、候选历史、最终规则与来源；
- 每次事件包含 `world_id`、`task_id`、`trace_id`、`rule_id`（适用时）、`evidence_ids`、`candidate_set_hash`、`source`、`algorithm_version`；
- 有 `observation_received`、`hypotheses_generated`、`hypothesis_eliminated`、`query_selected`、`rule_promoted`、`rule_executed`、`rule_abstained` 等可识别事件；
- 重要状态更新尽量原子写入，失败不能把半条规则当成已晋升；
- `student_induced` 规则与 `teacher_programmed` 底层机制分开记账；
- 原始失败事件、错误候选与撤销轨迹不得清空。

**注意**：现有 `fact_ids` 多由规则实现主动填写。本轮应核验“声称使用的证据”与实际读取的观察是否一致；不能仅因为日志里出现某个 ID 就认定它被用于推导。

## 5. 对外接口建议（允许等价实现，但要稳定、可测试）

建议为 V2 新增独立 JSONL CLI（可以在现有 Kotlin 程序中新增子命令，或单独入口）。语义至少应覆盖：

| 操作 | 作用 | 教师是否参与 |
|---|---|---|
| `discovery.start` | 导入公开属性 schema、已知样本、可查询对象，不含隐藏目标规则 | 否 |
| `discovery.hypotheses` | 返回当前可行候选、数量、证据理由 | 否 |
| `discovery.next_query` | 返回最有区分度的可查询对象及预查询选择依据 | 否 |
| `discovery.observe` | 吸收对某个已询问对象的标签、证据来源 | **只由教师/测试夹具提交单个结果** |
| `discovery.finalize` | 尝试晋升规则；若不可辨识则明确拒绝 | 否 |
| `discovery.predict` | 使用固化规则预测新对象，不调用教师 | 否 |
| `discovery.status` | 输出学习状态、来源和审计摘要 | 否 |

`discovery.start` 的输入可近似为：

```json
{
  "world_id": "demo-001",
  "feature_schema": {
    "颜色": ["红色", "蓝色"],
    "形状": ["圆形", "方形"]
  },
  "known_examples": [
    {"id":"A","features":{"颜色":"红色","形状":"圆形"},"label":true,"evidence_id":"e-A"},
    {"id":"B","features":{"颜色":"蓝色","形状":"方形"},"label":false,"evidence_id":"e-B"}
  ],
  "query_pool": [
    {"id":"C","features":{"颜色":"红色","形状":"方形"}},
    {"id":"D","features":{"颜色":"蓝色","形状":"圆形"}}
  ]
}
```

必须做到**信息隔离**：学生端的输入和状态文件不能包含 `hidden_rule`、`expected_label`、全部 `oracle_labels` 或独立测试答案。真实标签只在学生选定查询对象后，通过 `discovery.observe` 一条一条传入。

可定义 `observe` 的来源为 `teacher_oracle`，并校验 `evidence_id` 唯一、对象存在、查询状态正确；不允许教师一口气提交最终 Kotlin 源码。防止调用方绕过学习流程直接创建 `student_induced` 已晋升规则。

最终规则记录示例：

```json
{
  "rule_id": "induced-demo-001-001",
  "status": "promoted",
  "rule": {
    "op": "and",
    "clauses": [
      {"field":"颜色","eq":"红色"},
      {"field":"形状","eq":"圆形"}
    ]
  },
  "acquisition_method": "student_induced",
  "generator_method": "designer_programmed_hypothesis_search",
  "evidence_ids": ["e-A", "e-B", "e-C", "e-D"],
  "scope": "finite_attribute_schema",
  "schema_version": "discovery-v1"
}
```

上面是**数据格式示例**，不是向学生提供的目标规则模板。代码中不得直接硬编码“红色 AND 圆形”。

## 6. 五组必须覆盖的实验

### E1. 基本归纳与跨对象泛化

使用第 3 节 A/B/C/D，隐藏规则为“红且圆”。学生应先保持多候选，再通过询问确定规则。最终在新对象 ID 上离线预测，并与教师隐藏真值独立比较。

### E2. 信息不足与不可辨识

只提供 A=true、B=false，查询池为空或仅含不能区分候选的重复属性组合。学生必须明确 `ambiguous/unknown`，给出未能区分的候选与所需反例类型。**不能默认选择最简单或最复杂的候选并标记为学会**。

### E3. 证据冲突

同一 world、同一对象属性，依次收到 `true` 与 `false` 的教师标签。必须输出 `conflict`，保留两个证据来源；规则不得晋升。若后续提供“撤回某条证据”的机制，才能在可审计条件下恢复可辨识状态。

### E4. 真正换世界

至少改变：

- 全部对象 ID、名称；
- 颜色与形状的具体取值（例如 `绿色/黄色`、`三角形/正方形`）；
- 目标规则使用的具体取值与条件组合；
- 样本顺序、查询池顺序，以及正负样本比例。

必须验证学习过程不是检测 `world_id`、字面值 `红色`、训练对象 `A/B/C/D` 或固定查询顺序。可以增加第三个无关属性，检查学生是否能忽略与标签无关的条件；若有限语法不支持某类世界，须如实标记为超出假设空间。

### E5. 反例推翻已有候选

先提供会使某个错误候选显得合理的样本，再返回具有区分力的反例。要求候选淘汰与证据引用正确，旧猜想仍可在历史记录中复核。

以上五组应有自动化断言；还应建立仅靠对象 ID 记忆的基线与“教师直接给规则”的参考上界。不同方法使用相同的公开样本、候选池和查询预算；报告分别列出**准确率、覆盖率、拒答率、所需查询数、规则是否唯一、证据冲突率与无效晋升数**。

## 7. 考试纪律：防止再出现“漂亮但含义不清”的满分

**这里是本轮最重要的工程约束。**

### 7.1 两级验证

**公开开发测试（DeepSeek 可实现）**：

- 建立手工用例和随机生成器、固定种子可复现；
- 公开测试只能用于调试，不得称为独立第三方闭卷；
- 至少覆盖本任务书的 E1–E5，以及非法参数、重复 evidence ID、数据缺失、重启、日志正确性。

**冻结后的独立闭卷（由 Codex / ChatGPT 另行组织）**：

- DeepSeek 提交实现后冻结 commit、规则 DSL、候选策略和所有配置；
- 审计者独立生成尚未公开的世界/样本与真值计算器，不复用学生的 Kotlin 规则执行函数判分；
- 尽量使用不同的世界构造代码与不同的真值 oracle，避免测试器和学生共同犯错；
- 考试时禁止修改源码、配置、规则语法，且 `discovery.predict` 的教师/模型调用次数必须为零；
- 报告分清“开发测试通过”与“独立闭卷通过”；在审查者没有实际执行前，后者一律标 `not_run`。

### 7.2 要把测试失败细分

不能把任意 `error / unknown / conflict` 都视作“成功拒绝”。至少区分：

- `invalid_input`：参数错误；
- `insufficient_evidence`：证据不足、存在多个非等价候选；
- `no_discriminating_query`：可用查询不能减少歧义；
- `conflicting_evidence`：确实存在同一事实的互斥证据；
- `out_of_hypothesis_class`：真实目标不在支持语法内（该结论由考试器判定，学生不可偷看）；
- `internal_error`：实现失败。

将“拒答正确”与“规则推断正确”分开计分，**每项给出分母**，避免通过大量拒答拉高成绩。

### 7.3 必须报告的指标

每个 world 和总体分别输出：

- 输入样本数、学生实际发起的查询数、总教师标签返回数；
- 初始化/每次观察后的可行候选数；
- 晋升/未晋升世界数；
- 未见对象预测数及正确数、错误数、未知数（不要只给 accuracy）；
- 晋升规则与隐藏目标在**完整有限特征组合空间**内的等价性结果（由外部真值源检查）；
- 无证据晋升、错误来源归因、缺失 trace、意外教师调用、测试输入泄漏次数；
- 与 ID 记忆基线、教师直供规则参考上界的比较。

建议公开开发集中至少覆盖 **30 个不同世界**（多个 seed 和规则组合），再做完整属性组合穷举；这不是要求捏造 30 个成功案例，失败同样必须出现。没有外部闭卷结果前，不得宣称“已证明自主学习”。

### 7.4 一项额外的 V1 测试风险提示

我已核对旧 `tools/curriculum_batch.py`：

- `grade_case` 对 `expected_status="reject"` 接受任何 `error/unknown/conflict`，不会验证拒绝原因；
- 24 课生成函数中，大多数题目主要依赖固定模板，只有少数课程在生成函数中直接使用 `ctx.rng`；“不同 seed”并不自动等于广泛独立分布。

**本轮新考试器不能沿用这些宽松口径**。旧成绩无需修改或抹去；在 V2 报告说明其适用范围即可。

## 10. 最终验收条件（可机械检查）

**工程门槛**：

- 现有 V1 单元测试仍能通过（若未通过，说明是既有故障还是本轮回归）。
- V2 能单独运行，既有代码/规则不被覆盖。
- E1–E5 各有自动化测试和真实输出，日志能够关联到本次规则与证据。
- 构建、运行不依赖教师实时推理 API；可以用本地确定性 oracle 完成公开演示。
- 非法输入、冲突、未知被严格区分；未满足晋升条件不能产生已晋升规则。
- 所有结论都有真实程序输出支持，能复现输入和种子。

**学习门槛**：

- E1 中一开始必须有多个非等价、仍然可行的候选。
- 学生至少提出一次由候选分歧驱动的主动查询，查询决策发生在教师回答之前。
- 候选随着新证据按预期收缩，关键淘汰事件可溯源。
- 在证据足够时能晋升正确规则；证据不足或冲突时明确拒绝晋升。
- 规则不包含训练对象 ID，也不能通过查询已知标签缓存来替代规则。
- 新对象推理完全离线、零教师调用；报告记录穷举域上的正确数与错误数。
- 对比只记忆 ID 的基线，展示至少一类新对象泛化能力；不把这一个结果夸大为通用学习。

**审计门槛**：

- 真实记录教师提供了哪一条标签、学生自己做了哪一次候选选择；不得把教师算法或预置 DSL 冒充学生自主发明。
- 原始输入、结果、日志、源码版本和规则 hash 互相关联。
- “独立闭卷”由外部审查者实际执行之前，坚决保持 `not_run`。

## 12. 本轮不允许走的捷径

以下任意行为都会使“学生自主发现规则”的结论失效：

- DeepSeek 看见目标答案后，直接把“红且圆”的 if 条件写进学生实现，然后称之为学会。
- 直接让 DeepSeek 读完整训练集和隐藏标签，返回最终 Kotlin 函数，由学生加载执行，却标记 `student_induced`。
- 将 `world_id`、对象名称、固定颜色值映射为预存答案。
- 事先只保留正确候选，再假装经历了候选生成和筛选。
- 学生没有真正选择查询样本，教师却提前按标准答案路线喂给它样本。
- 借助宽松判分将 `unknown`、`conflict`、`internal_error` 混为正确拒绝。
- 调试失败后直接覆盖旧 attempt，或修改题库使先前失败不再发生却不留记录。
- 用同一套学生逻辑同时生成目标真值并裁判学生输出，作为“独立验证”。

## 13. 下一阶段方向，但现在不要实现

V2 最小闭环成立、经过外部闭卷后，再进入：

- **L1**：已有规则的自动选择与计划组合，而不是输入里直接指定每个 `op`；
- **L2**：扩展候选语法（`OR`、否定、数值阈值、关系链），并对搜索复杂度做预算控制；
- **L3**：主动寻找反例、撤销/修正规则、识别冲突证据的可靠性；
- **L4**：多种学习策略竞争、保留有价值的经验、在新任务上选择更有效的学习方法。

这套学习能力轨与“学前 → 小学 → 初中 → 高中”的知识课程轨并行。知识课程决定**学什么**，学习能力轨决定**怎么学**。当 V2 成立后，原来的学前教材、小学 72 单元才能真正被用于产生新规则的学习实验，而不只是测试预编写函数。
