# DeepSeek 对第一步学习的建议

日期：2026-11-04。来源：本机 DeepSeek Harness Agent；由研究者要求、Codex提供背景并发起咨询，不是学生自主提出。

## 提交给教师的背景与问题

我们正在做“逻辑AI”研究，想请你作为教师给第一步学习建议。项目背景：学生是Kotlin程序；目标是通过可观察、可验证、可迁移的代码/知识/技能更新，逐渐将外部教师能力固化到学生。初期允许教师指导，但必须区分教师贡献与学生自主发现。你是外部DeepSeek Agent教师，当前聊天中的Codex负责实现与审查。现有V0仅转发问题到你并原样返回，已连续两次询问“什么是苹果？”且各调用一次教师，无缓存或推理能力。
现在计划最小V1：对原始问题做精确匹配，首次向教师请教后用SQLite保存原始回复与来源、会话ID、未核验状态；相同问题重启后也能本地复用，其他问题必须miss并正常求助；支持关闭教师时已学问题仍可回答、新问题返回未知；保留--version v0作为基线。暂不做同义改写、概念图或推理。请用最多五条简短建议审查这个方案，指出第一步真正增长的能力及验收方式。不要调用工具、读取文件或写代码，直接回答。

## 教师原始建议（待评审）

**第一步真正增长的能力**：这个答案本身并不增长，真正增长的能力是：学生第一次能独立持有一项教师资产——**对“完全相同的问题”，在教师缺席、进程重启后仍给出与首次一致的答案，并且能追溯是哪一次教师调用、当前仍未核验**。可概括为“可复用、可追溯、对已学问题不依赖教师”。验收标准一句话：同一精确问题跨重启、含教师关闭重复 N 次，教师调用恒为 1 次，答案完全一致，来源可查，未核验标记在位。

**五条建议**

1. 先明确“相同问题”的定义，再保存数据。不做同义改写不等于不做规范化：必须固定空白、大小写、全半角、Unicode NFC、换行的处理，并同时保存 `raw_question` 与 `match_key`，并在记录里带上 normalizer 版本。否则“重启后仍能复用”无法验收，将来引入规范化还会让旧记录全部失效。

2. “未核验”应作为状态机中的一个状态来表达，而不是只存一个布尔标志。把 `answer` 与 `teacher_raw_response` 分开存储，并保存来源、模型、提示、会话、时间戳。本步所有答案都属于 teacher-provided，日志和界面应禁止写成“已学会”或“自主发现”，只能写“已缓存·未核验（来源：教师调用 #id）”——这正是区分教师贡献与学生自主发现的最小依据。

3. 关闭教师后的行为应形成明确规则，而不是回退逻辑。命中：返回答案、来源和未核验标记；未命中：返回结构化的 UNKNOWN，并带上原因码，不要返回空字符串，也不要编造内容，更不允许静默重试教师。三种状态——命中并在线、命中并离线、未命中并离线——都必须有对应断言。

4. 把 `conversation_id` 表示与教师对话的会话，与 `run_id` 表示学生进程的会话分开记录；命中/未命中、教师调用、来源都要记录为可统计事件。核心指标是“教师调用次数与不同 match_key 数量之间的关系”，重复提问时应趋于平缓。数据库结构要带 `schema_version`，答案与来源必须在同一个事务中写入，避免出现“有答案无出处”。

5. 用 `--version v0` 作为对照，运行同一套测试脚本并输出机器可比较的报告，把“连续两次问苹果却两次调用教师”直接写成回归用例。通过标准是 {已学,未学} × {教师开,关} × {重启前,后} 矩阵全部通过，且 v1 的教师调用数等于唯一问题数。本步不要引入任何“推理”指标，避免把缓存命中误读为智能增长。
