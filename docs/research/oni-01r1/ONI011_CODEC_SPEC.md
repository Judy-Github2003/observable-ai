# ONI-01.1 结构激活编码与字段证据

Codex，2026-11-18。一个公开的同值对照给出了两个不同的答案。询问证据深度时，在相同提示里把深度从 2 替换为 3，MiniCPM 的完整回答从 `2` 变为 `3`。第二个图复现了 1 到 3 的变化。询问证据来源时，四个注入样本全部答错。下文记录这两种观察各自能支持的解释。

## 编码如何进入模型

学生只接收公开事实与查询。语法解析在生成前进行，显式程序在 decoder block 的输出 hook 内执行。规则 `semantic.nearest_inheritance.v1` 取距离最近的整层证据，最多经过三条边，返回已找到、未知或同距离冲突。原始 decoder 的后续各层接收修改过的 residual，原始 LM head 和贪心解码生成文本。

| 条件 | 生成前向中的信号 | 额外答案条件化模型调用 |
|---|---|---|
| E0 · LEGACY_ANCHOR | 历史对照，当前候选值的上下文激活，block 27 单槽注入 | 有，解析成功时调用 |
| E1 · VALUE_NO_AUX | 当前胶囊的 value，无值时使用 status 字符串。每个子词占一个固定物理槽 | 0 |
| E2 · STRUCT_FORCED | E1 加上独立的角色、来源、深度和有序路径编码 | 0 |
| E3 · STRUCTURE_FIRST | 对查询实体做一次邻接表展开，排序直接父节点，编码查询、规则、未求解状态和该 frontier，无最终 value 或已选证据源 | 0 |

E1/E2/E3 的模型输入在同一道题上逐 token 相同，包括通用说明和 34 个下划线槽。输入模板提示模型读取 value 字段。显式字段只经过 embedding 查表、向量运算和 residual 注入。输入中的真实事实本身可以包含候选属性值。未识别语法时跳过编码。

## 各个槽位的内容

| 位置（0 起算） | 用途 | 表示 |
|---|---|---|
| 0–6 | status、query entity、property key、source、depth、path、rule id | 固定角色置换后的 2048 维向量。路径单独按节点顺序绑定 |
| 7–14 | 来源 | 从左向右按原顺序放置冻结源名称子词，右对齐 |
| 15–17 | 深度 | 同上，编码十进制深度 |
| 18–33 | 候选值或无值时的状态名称 | 同上，最多 16 个子词，多于 16 个时显式报错 |

编码使用带起始空格的冻结 tokenizer。词内子词向量均值附加 0.15 倍的位置置换均值，随后归一化。各角色/顺序的对应置换由 `SHA256(role:order)` 的前四字节确定，沿隐层维度循环平移。不同顺序的路径先绑定，再平均并归一化。source、depth 和 value 的可读子词槽使用原始 embedding 方向，有效字段左侧以空白 embedding 填充。缺失或被删除的字段保留模型原 residual。source 长于八个子词时，角色槽保留全称，独立可读槽只存前八个并记录溢出。

融合按每个有效槽分别计算 `h' = h + α (normalize(code) × ‖h‖ − h)`，回写 BF16。公开开发网格的最高完整匹配为 9/24，block 0 和 2 的 α=0.65 并列，按预设次序选 block 0。每道题每一生成步重新处理同一组提示槽，`use_cache=False`。基础权重与 codec 的训练更新均为零。门控另用 24 个公开 DEV 激活和适用性标签闭式拟合 2048 维方向与一个阈值，冻结阈值为 0.0889594592154026。

SHAM 在每个槽放入固定随机方向，按原干预的各槽范数缩放。WRONG 取另一个公开题的完整胶囊，按原干预的整体范数缩放。实际回写范数会受 BF16 舍入影响。ZERO/RESTORE 使用相同胶囊及解码设置，GATE 三组复用同一次门控决定。字段消融移除对应角色槽及其所有可读副本。无值胶囊中 status 同时是 value 槽的内容，移除 status 也会移除这一副本。反事实路径组同时改 source、depth 和 path，应按联合干预解读。

## 公开字段诊断

CPU 单测以同一公开值 `VerdAzur_703Q` 验证六个子词的顺序。独立替换 value、source、depth、path 或 status 时，编码张量 L2 距离分别为 2.432、1.755、0.884、1.115、1.367。对四个非 value 干预，16 个 value 槽都逐元素相同。事实顺序反转、加入不改变最近证据的回边，编码距离都为 0。重命名保留深度与结果，改变路径的编码。深度四的单一证据返回 UNKNOWN，同层两值冲突返回 AMBIGUOUS。

真实生成实验使用两个公开图，将最后的读取指令换成读取 source 或 depth。每个图、每个字段分别运行无注入、原字段注入、单字段替换注入。三组的提示、事实、显式原始值和解码预算相同。原生 LM head 产生的完整输出如下。

| 图 | 字段 | 原值 → 替换值 | 无注入 | 原字段注入 | 替换字段注入 |
|---|---|---|---|---|---|
| 1 | depth | 2 → 3 | UNKNOWN | 2 | 3 |
| 2 | depth | 1 → 3 | depth | 1 | 3 |
| 1 | source | willow → orchard | UNKNOWN | sprig | UNKNOWN |
| 2 | source | maple → orchard | maple hue VerdAzur_703Q | maple hue VerdAzur_703Q | VerdAzur_703Q |

事后诊断直接读取下一层收到的 BF16 张量，以实际注入前 residual 和两个公开候选重构各字段预测方向，按距离解码。两个图 × 两种读取任务 × 原字段/替换字段 × 五字段 × 两个生成步，80/80 次选中实际注入的字段。相同题与字段跨步重复，统计单位仍只有两个公开图。该诊断已知槽位和编码公式，仅证明字段送达后可辨识。depth 的成对输出另提供直接读取的因果证据，其可读子词槽已经承载深度数字。source 的读取在这些病例失败。独立的隐藏属性值任务检验跨世界整串答案收益，公开控制任务不能代替其验收。

## 复验入口

本地离线解释器配合 `PYTHONPATH=src` 运行 `tests/oni011/field_probe.py cpu` 和 `tests/oni011/field_probe.py readout`。后一项需要已选定的开发配置与本机 BF16。随后运行 `tests/oni011/audit_readout.py` 检查实际张量。原始 `cpu.json`、`cpu_vectors.safetensors`、`readout.json`、12 份原生生成 trace 和 `native_field_audit.json` 位于结果包的字段探针目录。学生实现入口为 `src/oni011/codec.py` 与 `src/oni011/injector.py`。
