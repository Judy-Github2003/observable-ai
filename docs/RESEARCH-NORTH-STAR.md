## 0. 一句话

我们研究的不是“再做一个 Agent”，也不是“复现某篇论文”，而是：

> **人工智能的内部知识应当如何表示、如何获得、如何变化，以及如何让这些过程对人真正可观察、可检查、可干预。**

---

## 1. 研究从哪里开始

我们最初从大语言模型的底层原理入手：Tokenizer、Embedding、Attention、神经网络权重、激活函数、反向传播与模型训练。理解这些技术之后，我们开始质疑现有架构在以下方面的局限：

- **知识表示**：知识被压缩在参数与稠密向量中，难以定位某一条具体知识；
- **内部可解释性**：能看到输入输出和注意力权重，不等于能读懂系统“依据什么知识、经过了什么步骤”；
- **直接修改能力**：很难精确地增加、修正或删除一条知识，而不牵动其他行为；
- **学习效率**：一次训练成本高，增量学习、纠错和迁移的代价不透明。

这些疑问促使我们探索另一种人工智能设计方法。**这不是因为我们已经证明 Transformer 或神经网络是错误的**，而是因为希望研究其他可能性；现有技术仍然是可以使用的工具，不是需要被否定的对象。

---

## 2. 我们真正关注的问题

### 2.1 内部知识表征

我们关心一种**多编码、分层、可递归展开的概念结构**：

- 一个概念可以同时关联字形、拼音、类别、属性、语义关系，以及多种可学习的表示；
- 一个概念可以参与多个结构模板，而不是被绑定在单一谓词或单条规则上；
- 结构应当既能被人检查，也能被程序操作，而不是只能通过输入输出间接推测。

这里的“多编码”不限定实现形式：可以是符号字段、关系边、类型化记录、向量视图，或它们的组合。关键在于：**不同编码之间要有明确、可追踪的对应关系**，而不是把一切压进一个无法拆解的稠密表示。

### 2.2 可观察、可解释、可干预

我们希望系统能够：

- 定位并检查它拥有哪些知识、这些知识来自哪里；
- 在具体执行时说明使用了哪条知识、哪些事实依据、经过了哪些步骤；
- 观察推理与学习状态，理解哪些结构发生了变化、为什么变化；
- 对这些结构进行修改，并验证修改后的行为是否符合预期；
- 在发现错误时撤销或降级相应知识，并看到影响范围。

需要区分三个层次，不能混为一谈：

| 层次 | 含义 | 不等于 |
|---|---|---|
| 可记录 | 有日志、事件、哈希和版本 | 可解释 |
| 可解释 | 人能理解“为什么这样判断” | 可干预 |
| 可干预 | 能安全地修改并验证修改结果 | 自动正确 |

当前仓库已经具备的主要是**工程可记录性**（事件、步骤日志、规则锚点、哈希、版本），这只是第一层，不能直接宣称已经实现认知层面的可解释或可干预。

### 2.3 自主知识获取与学习

长期目标是让系统逐渐能够：

- 发现未知：识别“我不知道”或“现有知识不足以判断”；
- 提出多个猜想，而不是只产生一个答案；
- 主动寻找证据、设计区分性观察；
- 验证、修正、淘汰知识，并保留失败记录；
- 学习如何改善自己的学习过程（学习策略本身也成为可研究对象）。

“自主”必须有分级和归因：开发者预置的算法、教师提供的能力、学生组合出的具体程序、学生从证据中归纳出的规则，必须分开记录。**算法自主不等于具体知识自主。**

### 2.4 开放的计算机制

我们不排斥 Embedding、概率判断、神经网络、反向传播或大语言模型。需要时完全可以使用它们。

我们反对的是：**让整个认知系统的关键知识与行为只能依赖难以直接检查的黑盒机制。** 一个可接受的方向是混合的：

- 黑盒可以承担感知、相似度、候选生成、近似判断等任务；
- 但关键知识至少应有一条可检查、可修改、可验证的显式通路；
- 黑盒输出进入系统时，只能作为**不可信候选**，不能直接成为事实或已激活能力。

### 2.5 知识、行动与学习策略的三分法

“知识 / 行动 / 学习策略”是我们分析问题的重要框架：

- **知识**：系统认为世界是什么样（事实、概念、关系、规则、证据）；
- **行动**：系统能做什么（查询、判断、组合执行、外部工具调用）；
- **学习策略**：系统如何改变前两者（提出假设、选择证据、抽象、修正）。

这个三分法是**分析框架**，不要求实现成三个独立进程，也不意味着每一类都必须用同一种表示或同一种语言实现。它的主要作用是防止把“会执行”误认为“会学习”，把“存了知识”误认为“理解了知识”。

## 3. 已确定的研究目标

以下方向已经确定，不随单篇论文或单次实验结果改变：

1. **以可检查的内部结构为核心。** 关键知识不能只存在于不可拆解的稠密表示中；至少要有一部分知识能被定位、查询、修改和验证。
2. **可观察、可干预是硬要求，不是附加功能。** 每次知识变化和能力使用都应可追溯、可复核、可撤销；日志与审计是基础设施，不是研究成果本身。
3. **自主性必须可归因。** 严格区分 `designer_primitive`、`teacher_proposed`、`student_composed`、`student_induced`、`student_abstracted` 等来源；教师写的能力不能记成学生自主学会。
4. **学习结果必须可验证。** 候选、验证、激活分离；系统不能自己宣布自己通过；未执行的检查写 `not_run`。
5. **对外部模型与工具保持开放。** 不排斥 LLM、向量或神经网络；但外部输出一律是不可信候选，必须经过同样的检查和验证。
6. **长期积累，不覆盖历史。** 知识与能力版本化；旧版本、失败记录和撤销记录保留，修正通过追加新版本完成。

这些目标描述的是**研究约束**，不是已经确定的架构。

## 4. 当前工程实现是什么、不是什么

### 4.1 已经实现的部分（截至 2026-11-05）

| 阶段 | 内容 | 状态 |
|---|---|---|
| V0 | 把问题转发给教师 | 保留为基线 |
| V1 | 原文精确匹配的问答记忆（SQLite） | 通过 |
| V2 | 受限假设空间内的规则归纳（单/双条件 AND、三值逻辑、主动查询） | 公开开发通过，独立闭卷 `not_run` |
| B0 M0–M2b | 类型化 IR、解释器、SQLite 能力注册表、可信验证套件、验证入库、激活门禁、`executeActive` | 已实现并提交 |
| B0 M2c–M4 | 撤销与传递失效、有界组合与证据筛选、L1/L2 压缩；L3 `not_implemented` | 已实现并提交 |
| B0 M5–M6 | A/B/C 同预算基准、冻结与交接 | 已实现并冻结 |

B0 的具体能力包括：11 类节点的 Typed IR、`Bool3 / String / Int64 / Record` 类型、强 Kleene 三值语义、canonical hash、版本锁定的 `call`、资源预算、不可变能力版本、依赖表、可信验证套件、验证与激活记录、正式执行入口。

### 4.2 B0 在项目中的位置

B0 是**当前阶段的可验证能力执行与学习实验基础设施**：

- 它让“能力”有类型、版本、依赖、验证和激活记录；
- 它让“学生组合出的程序”可以在不请求教师逐题写代码的情况下被检查、验证和执行；
- 它服务于后续实验，但**不等于**新的知识表征架构，也不等于完整的自主学习系统。

B0 的完成只代表相应工程基底与限定实验完成，不代表我们已经解决了概念表示、开放世界学习或通用理解。

### 4.3 当前明确没有的东西

- 没有多编码、分层、可递归展开的概念结构；
- 没有自主建立或修改表征结构的机制；
- 没有把向量/神经网络与显式结构协同起来的实现；
- 没有开放世界中的自主假设生成与知识修正；
- 没有证明“可执行、可记录”已经等于“可解释”；
- 没有独立闭卷验证（`independent_closed_book = not_run`）。

把这些中的任何一项说成“已经完成”，都是方向漂移和成绩冒领。

## 5. 尚待实验验证的假设

以下都是**假设**，不是结论。每一条都应设计可失败的实验；负面结果同样是有效结果。

- **H1（表征）**：相比扁平标签或纯稠密表示，分层、多编码的概念结构能在样本效率、迁移或可干预性上带来可测量的改善。
- **H2（混合）**：显式结构与向量/神经网络混合，可以在保留关键知识可检查性的同时，获得感知与相似度上的灵活性；两者不是二选一。
- **H3（自主建构）**：概念结构可以通过一组有界、可审计的操作（新增、合并、拆分、建立关系、退役）被自主建立和修改，并且修改结果可以被验证。
- **H4（迁移）**：新获得的知识能够参与后续推理、迁移和再学习，并在同预算对照中表现出可测量的收益，而不只是让程序变短或日志变多。
- **H5（可观察性保持）**：随着学习持续进行，系统仍能保持有意义的可观察性与可干预性，而不是退化成“日志齐全但没人能理解”的状态。

这些假设需要具体的任务、指标和对照实验来检验；在实验完成前，不得写成已实现能力。

## 6. 开放的技术选择

以下问题**尚未决定**，应由后续实验回答，而不是现在锁定：

- 概念结构的具体形式：类型化记录、图/超图、关系数据库、向量视图、VSA 式分布式表示，或混合方案；
- 向量与神经网络参与的程度和位置：感知、相似度、候选提议、 grounding，还是完全不参与；
- 学习算法族：归纳逻辑编程（ILP）、程序合成、版本空间/贝叶斯方法、元学习、认知架构中的某一部分，或新的组合；
- 知识、行动、学习策略是统一表示还是分离表示；
- 存储与查询：SQLite、图数据库、向量索引，或分层组合；
- 评测方式：新世界任务、干预实验、成本对照、独立闭卷的具体形式。

ILP、元学习、VSA、Concept Bottleneck、认知架构等是值得研究的参考技术，**不是已经确定必须集成的方案**。看到一篇新论文就宣布“本项目就是它的实现”，是我们要避免的漂移方式。

## 7. 明确不应进行的误解性扩展

1. **Kotlin 是现阶段的重要实现与行动载体，但不等于整个 AI 的知识都必须表示为 Kotlin 程序。** 概念、关系、证据和学习策略可以有其他表示形式。
2. **B0 的 Typed IR 是能力执行表示，不等于完整的概念与认知表示。** 不要因为 IR 能表达规则，就宣称它已经能表达概念结构。
3. **我们不反对向量，但不希望把复杂知识不加区分地全部依赖难以解释的稠密表示。** 向量可以是工具，不能是唯一真相源。
4. **Skill 自进化、程序压缩、外部记忆和 Agent 不是最终研究目标。** 它们是可能的手段或基础设施；完成它们不等于回答了“知识如何表示、如何学习、如何变化”。
5. **ILP、元学习、VSA、Concept Bottleneck、认知架构等是参考技术，不是必须集成的全部方案。** 不要用技术清单代替研究问题。
6. **不要把教师编写的能力归因于学生自主学习。** 归因必须按真实来源记录，候选、验证、激活都不能改写来源。
7. **不要把“可执行、可记录”直接等同于“真正可解释”。** 事件和哈希证明的是可追溯，不是可理解。
8. **不要把“概念关系查询”直接等同于“自主概念学习”。** 能查关系，不代表系统自己建立了概念。
9. **不要把 B0 完成说成新知识表征架构或完整自主学习系统已经实现。**
10. **不要因为近期出现某些先进论文，就把项目定义成某一种现有算法的实现。** 我们研究的是问题，不是论文的复刻。

## 8. 方向自检：每个新阶段开始前问五个问题

1. 这件事是在加深对“内部知识如何表示、如何学习、如何变化”的理解，还是只是增加工程功能？
2. 它让关键知识更可检查、更可干预，还是把更多关键行为推入黑盒？
3. 自主性归因是否诚实？开发者、教师、学生各自的贡献是否分得清？
4. 结论是否可验证、可失败？是否允许并保留负面结果？
5. 我们是在把某种技术当手段，还是已经把项目等同于某种技术？

如果回答不清，应先回到实验设计，而不是先写代码或先写报告。
