# Observable AI 项目总档案

更新基准：2026-11-16  
正式名称：**Observable AI（可观测人工智能）**  
旧称说明：早期材料中出现“自主逻辑 AI”“逻辑驱动学习者”“ARLS”等名称或前缀。项目负责人已明确 Observable AI 才是正确的正式项目名称。历史文件名、任务 ID 和实验目录不批量改名，以免破坏溯源。

## 1. 项目是什么

Observable AI 不是普通 RAG 聊天机器人，不是单纯规则引擎，也不是把某个外部 Agent 框架包装成产品。

它的长期目标是研究一种**能够通过自身经验获得知识、形成可执行能力、验证并修订结论，最终改进自身学习方法的人工智能系统**。

系统可以使用神经模型作为理解、生成、候选提出和规划能力来源；但学习成果不能只存在于神经模型的一次回答中。Observable AI 必须把可复用成果沉淀为自身可追踪的知识、技能、程序、策略和表征，并用未见任务检验是否真的学会。

## 2. 当前最重要的研究目标

项目负责人 2026-11-16 最新确认：

> 当前先务实地验证学习能力，把逻辑、数学、代码、语义四大基础能力扎扎实实学好。重点是 Observable AI 系统本身学会，而不是仅仅让 MiniCPM 学会。

四大基础能力是当前研究重点：

1. **逻辑**：概念间关系、命题、条件、推导、否定、反例、未知状态、规则形成。
2. **数学**：运算、函数、关系、规律、猜想、验证、证明、算法化。
3. **代码**：程序表达、类型、函数、算法、组合、执行、调试、程序能力复用。
4. **语义**：词形、义项、概念、属性、关系、定义、实体、事件、命题及其适用范围。

四者不是四套孤立的产品模块。目标是让同一套学习循环在四个领域中工作，并逐步学习它们之间的可验证转换关系。

## 3. 当前模型与 Agent 的定位

### MiniCPM5-2B Q4

- 当前基础神经模型候选/执行模型。
- 负责语义理解、候选生成、解释、代码草拟和行动规划等。
- 不是 Observable AI 本身。
- 当前阶段优先固定权重，观察外部学习系统是否能提升整体任务表现。
- 权重更新、LoRA、持续训练属于中长期选项，目前不着急。

### DeepSeek Harness（DSH）

- 当前临时借用的 Agent/工具运行环境。
- 用于快速验证 MiniCPM 是否能读写文件、运行命令、执行测试、观察结果和恢复失败。
- 不是 Observable AI 最终的 Agent，也不是学习引擎。
- 最终自研 Agent 是长期目标，但目前不应抢占四大基础能力学习的研发资源。

### Kotlin 学习系统与验证设施

- 现有 Kotlin 代码、知识库、能力表示、执行与验证机制是已有工程资产。
- 不应因使用 Harness 而放弃。
- Kotlin 可以继续作为宿主、验证器、账本和程序执行环境；学习算法是否必须只用 Kotlin 尚未被证明，未来可按需要引入其他语言，但接口与证据格式必须统一。

## 4. 最终系统目标（长期，不是当前交付）

Observable AI 最终应是一个完整、独立、可持续学习的人工智能系统：
- 可独立运行；
- 有自己的学习引擎和 Agent；
- 可调用或替换不同神经模型；
- 也能作为模型/服务接入 Claude Code、DeepSeek Harness 或其他外部 Agent；
- 学习成果、知识和策略不被某个外部 Agent 的会话记录锁定；
- 能够提出、实现、验证和复用新能力；
- 长期研究是否能自主改进学习机制。

这些是长期目标，不代表当前已经实现。

## 5. 核心研究原则

1. **模型输出是候选，不是事实裁判。**
2. **未知不等于否定，也不等于错误。**
3. **证据、推导、假设和结论必须分开记录。**
4. **所有可晋升知识/能力必须有来源、范围、验证状态、版本和依赖。**
5. **错误和阴性结果必须保留，不能为追求全绿而改写。**
6. **学习能力要通过未见任务迁移验证，不以知识条数、代码行数或 JUnit 通过数代替。**
7. **模型权重、外部 Agent、存储后端均应可替换；不能把外部基础设施当成 Observable AI 的永久归属。**
8. **Git 是强制研发记录系统；每轮变更都要可追溯、可回滚、可审计。**

## 6. 历史研究线索

- 早期逻辑 AI / Logic-Driven Learner：显式知识、推理、研究循环、外部教师。
- V1：精确问答记忆与教师回退；不是语义学习。
- V2：有限属性 schema 上的假设搜索、查询、淘汰和晋升；受设计者给定的假设空间约束。
- B0：类型化能力 IR、类型检查、解释执行、能力注册、版本与依赖治理、验证/激活/撤销门禁、有界组合与程序库学习基础。
- E3 / SD-03：诊断、查询、局部修复、递归组合和新表征相关研究；有正有负，不能把有限结果升级成自主表征形成。
- FMPS / CHAR-LEARN / BMNV / ABDMNV 等：覆盖多视图、字符/语义、语法、组合能力等方向；必须按各自报告标记证据，不合并成“已学会”。
- SL03 / SL04：保留为历史实验族和当前代码资产；详细状态由本机 artifact inventory 与报告重建。
- G1.1 / G1.2 / G1.2r：MiniCPM 接入和结构化程序生成/反馈实验。
- ACT-01：MiniCPM + DSH 极简模式的真实工具操作评估；尚未正式完成。

## 7. 当前阶段的成功定义

在 MiniCPM 权重固定的条件下，经过 Observable AI 学习循环后，系统能够：
- 获得原先没有的知识/规则/程序技能；
- 以可追溯方式保存和验证；
- 在未见样本、未见组合或新任务族中复用；
- 相比同一模型的零历史基线和普通检索基线产生可重复收益。

第一阶段不要求完全摆脱神经模型，也不要求自主创造全新的学习算法。先证明系统自身可以学习四大基础能力。
