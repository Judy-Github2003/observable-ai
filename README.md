# Observable AI

**中文** · [English](README.en.md)

**研究可观测的学习系统：让知识、计算和能力更新都有可检查的依据。**

Observable AI 从一个问题出发：当系统学会一道原本不会的题，我们能否找到起作用的知识、规则与计算，并在出现错误时有针对性地修正，同时保留已有能力？

项目围绕语义、逻辑、数学和代码开展实验，逐步扩展到 Linux 操作、常识与历史。研究包括显式知识与规则、MiniCPM 神经执行器，以及采用 Unicode/Class 双表示的自研模型。我们希望系统能够学习知识、执行方法，并改进自己的学习策略；这些目标分别通过受控实验验证。

> **研究状态 · 2026-11-21**  
> 当前仓库提供 Kotlin 学习内核、ONI 模型注入实验和 Classizer3D 可运行原型。最新 ARLS R03 研发材料已推进到约 **987M 参数**的模型与训练计量原型，完整试跑包尚未发布到本仓库；下文将其单列为研发快照。R03 正式主干优化器更新数为 **0**，尚无训练完成的通用模型或相对基线的能力优势结论。

## 我们在研究什么

| 问题 | 研究方式 | 需要观察的结果 |
|---|---|---|
| 知识如何参与答案生成？ | 显式规则、来源记录、Class 表示与神经桥 | 更换、撤去或恢复证据后，最终答案是否按预期变化 |
| 新知识怎样进入系统？ | 参数训练、结构化知识注册、外部查询及其对照 | 新知识学习、旧能力保持、修改范围与更新成本 |
| 复杂问题能否使用更多计算？ | 共享计算核、动态深度与三维单调预算 | 同等正确率下的实际计算量、时延与停止错误 |
| 错误能否更容易定位？ | 输入、候选、路由、执行及版本记录，配合定向干预 | 诊断和修复是否比对照更有效，以及是否影响其他任务 |

“可观测”指可检查的数据来源、显式状态、执行记录与干预结果。日志、梯度或激活变化本身并不能证明系统理解了一个概念，也不能单独证明因果解释成立。

## Class：定义与具体使用分开

Classizer 探索带有词形、释义面、属性、关系和来源的结构化表示。一个 **Class 定义**可以保留多个可能含义；一次 **Class 使用**则绑定具体提及、实例、作用域、候选释义面、活动面和证据。

以“苹果”为例，目标行为是：

| 输入 | Class 定义 | 这次使用的解释 |
|---|---|---|
| 我想买一个苹果。 | 保留水果、电子产品相关的候选释义面 | 证据不足，保持未定 |
| 我的手机坏了，我想买一个苹果。 | 仍使用相同定义 | 手机上下文支持电子产品相关释义面 |
| 同一段话分别谈到吃苹果和买苹果手机。 | 多次提及可以共享定义 | 每次提及独立绑定，不能互相覆盖 |

“手机”还可以通过带条件的关系关联到“苹果”，例如候选品牌关系；这不意味着任意手机都属于该品牌。未知、未定、多面共激活和证据冲突需要分别表达。

以上是设计与评估契约。现有结构和小型用例支持表达其中一些情况，开放文本中的自动跨度发现、实例绑定与上下文消歧仍需训练和评测。

### ONI 的历史基线

ONI-01 在 12 道适用留出题中，强制注入全部改变了下一层接收的激活，但模型与基线都只答对 **2/12**；自动门控触发 **0/12**。ONI-01.1 在两个新世界的 24 道适用隐藏题上，强制注入与匹配基线同为 **2/24**。置零、恢复在全部 **56** 道题中复现了各自对照输出；门控识别了 24 道适用题，同时在 32 道对照题中误开 21 次。

这些记录帮助区分“证据接入了计算”“门控选对了时机”和“最终答案得到改善”。完整条件见上方实验报告。

## R03 研发快照

以下数字来自维护者提供的 `ARLS_R03_PILOT.zip`、编码比较和机制说明，经源码检查及有限的独立复核整理。**这些材料尚未完整发布到本仓库，因此本节是进展说明，公开复现入口仍以下方现有代码为准。**

| 项目 | 当前记录 | 解释 |
|---|---|---|
| 模型规模 | **987,252,481** 个参数 | 源码与参数算术一致；38 个独立块，其中 4 个中间块支持重复调用 |
| 表面入口 | **13,929** 个表面符号槽位 | Unicode 标量词表、UTF-8 字节回退与结构控制符号；保留原文可逆性 |
| Class 热表 | **65,536** 个 Class、**107,018** 个词形 | 候选 ID 经 128 维可训练表示与神经桥注入主干；完整词库规模不等于已内化知识量 |
| 试跑材料 | **3,072** 条输入、8 个分片 | 参考 token 字段合计 **492,368**，该数字为记录重汇总；不是大规模预训练语料就绪证明 |
| 本次复核 | **3,072/3,072** 条输入精确往返；82 个清单文件哈希通过 | 验证编码和交付材料，不是语言能力评分 |
| 正式主干训练 | **0 次优化器更新** | 小模型与工程路径检查不能替代正式主干的训练结果 |

当前 TC（表面单位 + Class）主干仍预测下一表面单位，Class 通过神经桥参与计算。结构化输出已有契约与检查器；可靠的结构化生成、直接 Class 预测和可变计算宽度仍需训练与评估。Token 与 Class 是否互补、何时可以替换，需要分别验证。

共享核默认执行一次，球形预算默认关闭，R03 默认训练尚未包含路由与停止控制器的任务学习目标。这里的“三维单调球形预算”用于限制共享计算的前进与停止；它与公开 Classizer3D v0 的调用方指定调度坐标是不同实验。逻辑停止也不能直接折算成同等比例的 GPU 节省。

### 编码长度：保留不利结果

在 156 条排除了与拟合材料精确原文重叠的小型开发输入上，冻结编码器记录如下：

| 表示 | 总输入单位数 | 精确还原记录 |
|---|---:|---:|
| Unicode 表面入口（TC/NC） | 44,020 | 156/156 |
| BPE 入口（BT/BN） | 19,388 | 156/156 |
| 当前 CL 文本序列化对照 | 901,328 | 156/156 |

该样本中，Unicode 入口约为 BPE 长度的 **2.27 倍**。当前 CL 会逐字符写入带 Class 引用的 JSON，再做表面编码，因此约为 Unicode 入口长度的 **20.48 倍**；它尚不能代表紧凑的直接 Class ID 编码。

这个检查只测长度与可逆性。开发样本较小且非随机，两种码表的词表规模和拟合材料也不完全相同；它不能给出模型能力、训练效率或前端优劣的普遍结论。完整比较材料仍待公开。

## 快速开始

以下命令使用当前仓库已有代码。先克隆并进入仓库：

```bash
git clone https://github.com/Judy-Github2003/observable-ai.git
cd observable-ai
```

### 1. 运行无需模型权重的检查

使用 Python 3.10 或更新版本，先检查 Classizer3D 的类型与序列化契约；该项只需标准库：

```bash
python -m unittest discover -s research/classizer3d/tests -p test_schema.py -v
```

ONI-01 的继承规则检查也只需 Python 标准库。Linux / macOS：

```bash
PYTHONPATH=src python -m unittest discover -s tests/oni01 -p test_capsule.py -v
```

Windows PowerShell：

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests/oni01 -p test_capsule.py -v
```

### 2. 运行 Classizer3D 神经原型

在合适的 Python 环境中安装 PyTorch，CPU 即可运行这些小型用例：

```bash
python -m pip install torch
python -m unittest discover -s research/classizer3d/tests -v
python -m research.classizer3d.neural
```

这是结构与梯度路径检查，不会训练 R03 主干，也不需要下载 MiniCPM 权重。详细范围见 [Classizer3D README](research/classizer3d/README.md)。

### 3. 构建 Kotlin 学习内核

需要 JDK 21。首次构建需要联网获取依赖。

```bash
bash ./gradlew --no-daemon installDist
```

Windows PowerShell：

```powershell
./gradlew.bat --no-daemon installDist
```

日常验证应使用 [工程测试说明](docs/engineering/TESTING.md) 中的针对性入口。无筛选的 `gradlew test` 会运行较长的科研回归，请先阅读说明。

## 接下来的验证

1. **公开可复现实验。** 整理 R03 源码、必要夹具、数据来源、验收记录和可运行入口，使结果能被第三方检查。
2. **比较不同表示。** 在相同原文和监督下比较 BPE、Unicode、Class 与混合路径，同时报告参数、实际计算量和最终答案质量。
3. **测量学习与保持。** 训练后评估新表达、多实例绑定、知识更正与撤销，并重新检查旧能力。
4. **验证计算与归因收益。** 比较固定深度、标量预算和球形预算；针对真实错误检验定向干预、修复范围和成本。

MiniCPM 保留为神经执行器与实用基线。自研模型路线和已有模型集成路线都需要依据实验决定下一步。
