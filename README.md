# Observable AI

**中文** · [English](README.en.md)

Observable AI 研究一个问题：当小模型答对一道原本不会的题，我们能否沿着代码和实验记录，找到究竟是哪条规则、哪份证据、哪一次计算起了作用？

项目从语义、逻辑、代码、数学四个方向的规则学习出发。当前的 **Observable Neural Injection（ONI）** 实验将可检查的规则接入 MiniCPM 的 Transformer 前向计算，冻结基础权重，观察模型怎样使用证据生成答案。

## 从一条规则看项目

假设“麻雀属于鸟，鸟属于动物”，已知鸟的颜色是蓝色，动物的颜色是棕色。查询麻雀的颜色时，已验证的继承规则沿父关系最多查三条边，在最近一层找到证据就停止。本例返回蓝色，同时留下证据来源“鸟”、距离 1 和路径“麻雀 → 鸟”。

ONI-01.1 让模型读到一份带空栏位的记录。在选定 Transformer 层，代码把证据来源、深度、路径和属性值编码到这些栏位的隐藏状态。模型继续计算并逐 token 生成答案。对同一道题开启注入、把增量置零、再恢复原增量，就能检查哪些输出变化随干预消失和重现。

## 实验进展

| 研究问题 | 观察结果 |
|---|---|
| 四个领域形成的显式规则能否执行？ | 在限定题型中，直接指定冻结规则，32 道复用题和 16 道边界题共答对 48/48。通过 MiniCPM 调用能力时，复用题答对 9/32，其中 8 题有对应的能力调用记录。 |
| ONI-01 的注入是否进入真实模型计算？ | 对 12 道适用留出题，强制注入全部改变了下一层收到的激活。模型与基线均答对 2/12，自动门控触发 0/12。 |
| ONI-01.1 能否让模型利用结构化证据？ | 两个新世界共 24 道适用隐藏题，强制注入与匹配基线均答对 2 道。置零与恢复在全部 56 道题上复现各自对照输出。门控识别了全部 24 道适用题，同时在 32 道对照题中误开 21 次。 |

## 本地运行

在仓库根目录运行下列命令，即可用 Python 标准库检验 ONI-01 继承规则。测试覆盖最近证据、冲突、三步边界和环。

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests/oni01 -p test_capsule.py -v
```

Kotlin 学习内核需要 JDK 21。使用仓库自带的 Gradle Wrapper 构建本地可执行程序，首次构建需联网获取依赖。

```powershell
./gradlew.bat --no-daemon installDist
```
